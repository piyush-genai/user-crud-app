## 📄 **File-by-File Explanation**

### **1. app/main.py** (Main Application File)
**Purpose**: Entry point - wires everything together

**What it does**:
- Creates FastAPI application
- Connects MongoDB on startup
- Includes all API routes
- Handles errors globally (8 error handlers)
- Adds request tracing (unique ID per request)
- Configures CORS for browser access
- Sets up logging

**Key Feature**: Lifespan management - connects to MongoDB when app starts, disconnects when app stops

---

### **2. app/models/user_models.py** (Data Models)
**Purpose**: Defines data structure and validation rules

**What it contains**:
- **UserCreate**: Model for creating users (all fields required)
- **UserUpdate**: Model for updating users (all fields optional)
- **UserResponse**: Model for API responses
- **DeleteResponse**: Model for delete confirmations

**Validation Examples**:
- Salary must be > 0
- Employee ID must be unique
- Joining date must be between 1900-2100
- Address must be 10-500 characters

---

### **3. app/repositories/user_repository.py** (Database Layer)
**Purpose**: All MongoDB operations happen here

**What it does**:
- Connects to MongoDB with retry logic (3 attempts, exponential backoff)
- Creates unique index on employee_id
- **CRUD Methods**:
  - `create()` - Insert new user
  - `find_by_id()` - Get user by MongoDB ID
  - `find_by_employee_id()` - Get user by employee ID
  - `find_all()` - Get all users
  - `update()` - Update user fields
  - `delete()` - Remove user

**Key Feature**: Async operations (non-blocking, handles many requests simultaneously)

---

### **4. app/services/file_handler.py** (File Upload Handler)
**Purpose**: Manages profile photo uploads

**What it does**:
- **Validates file type**: Only JPEG, PNG, WebP allowed
- **Validates file size**: Maximum 5MB
- **Generates unique filename**: `{user_id}_profile_{timestamp}.{ext}`
- **Saves to disk**: In `uploads/` folder
- **Deletes old photos**: When user uploads new one

**Security**: Prevents malicious file uploads (executables, scripts)

---

### **5. app/services/user_service.py** (Business Logic)
**Purpose**: Coordinates between API, database, and file handler

**What it does**:
- **Enforces business rules**:
  - Check employee_id is unique before creating
  - Delete old photo before uploading new one
  - Return 404 if user doesn't exist
  - Return 409 if employee_id already exists
- **Translates errors**: Database errors → HTTP error codes
- **Coordinates operations**: Calls repository + file handler

**Example Flow**:
```
User uploads photo
  ↓
Service checks user exists
  ↓
Service deletes old photo
  ↓
File handler saves new photo
  ↓
Repository updates database with new URL
  ↓
Service returns updated user
```

---

### **6. app/routers/user_router.py** (API Endpoints)
**Purpose**: Defines the HTTP endpoints

**What it does**:
- Maps HTTP methods to functions
- Defines URL paths
- Specifies request/response models
- Provides API documentation with examples
- Calls service layer methods

**Example**:
```python
@router.post("/users", status_code=201)
async def create_user(user_data: UserCreate) -> UserResponse:
    return await user_service.create_user(user_data)
```

**Feature**: Auto-generates Swagger UI documentation

## 🎬 **Request-Response Flow Example**

### **Example: Create User**

**1. Client sends request**:
```http
POST http://localhost:8000/users
Content-Type: application/json

{
  "user_name": "John Doe",
  "employee_id": "EMP001",
  "salary": 75000.50,
  ...
}
```

**2. Router receives request**:
- Validates JSON structure
- Passes to service layer

**3. Service layer**:
- Checks employee_id "EMP001" is unique
- Calls repository to create user

**4. Repository layer**:
- Inserts document into MongoDB
- Returns created user with _id

**5. Service layer**:
- Converts MongoDB ObjectId to string
- Returns UserResponse model

**6. Router sends response**:
```http
HTTP/1.1 201 Created
Content-Type: application/json

{
  "_id": "507f1f77bcf86cd799439011",
  "user_name": "John Doe",
  "employee_id": "EMP001",
  "salary": 75000.50,
  ...
}
```

**Total time**: ~50-100ms

## 🛡️ **Error Handling**

We handle **8 types of errors**:

| Error Type | HTTP Code | Example |
|------------|-----------|---------|
| Validation Error | 422 | Salary is negative |
| Not Found | 404 | User ID doesn't exist |
| Conflict | 409 | Duplicate employee_id |
| File Too Large | 413 | Photo > 5MB |
| Invalid File Type | 422 | Uploaded .exe file |
| Database Unavailable | 503 | MongoDB is down |
| Invalid ObjectId | 422 | Malformed user ID |
| Internal Error | 500 | Unexpected bug |

**All errors return structured JSON**:
```json
{
  "detail": [
    {
      "field": "salary",
      "message": "ensure this value is greater than 0"
    }
  ]
}
```

## ❓ **Anticipated Questions & Answers**

**Q: Why did you use FastAPI?**
A: FastAPI is modern, fast, has auto-generated docs, built-in validation with Pydantic, and supports async operations for better performance.

**Q: Why MongoDB over SQL?**
A: MongoDB's flexible schema works well for user profiles, has built-in ObjectId, and integrates easily with Python via Motor driver.

**Q: How do you ensure employee_id is unique?**
A: Two-layer enforcement: MongoDB unique index at database level + service layer check before creation.

**Q: What happens if MongoDB goes down?**
A: Connection retry logic (3 attempts with exponential backoff). If all fail, API returns 503 Service Unavailable.

**Q: How do you handle large file uploads?**
A: Validation before storage: reject files > 5MB with 413 error, reject non-image files with 422 error.

**Q: Can you update just one field?**
A: Yes, PUT endpoint supports partial updates using Pydantic's `exclude_unset=True`. Only provided fields are updated.

**Q: How do you track requests?**
A: Each request gets unique UUID, included in logs and response headers (X-Request-ID).

**Q: Is this production-ready?**
A: Yes - has error handling, validation, logging, documentation, security checks, and tested functionality.

## 🎓 **Technical Terms to Know**

- **REST API**: Architectural style using HTTP methods (GET, POST, PUT, DELETE)
- **CRUD**: Create, Read, Update, Delete operations
- **FastAPI**: Modern Python web framework
- **MongoDB**: NoSQL document database
- **Pydantic**: Data validation library
- **Swagger UI**: Auto-generated API documentation interface
- **Async**: Non-blocking code execution
- **ObjectId**: MongoDB's unique identifier format (24-character hex)
- **Repository Pattern**: Data access abstraction
- **HTTP Status Codes**: 200 (OK), 201 (Created), 404 (Not Found), etc.
